# 격리 후보 실험 및 재학습 v0.1 설계

## 목적

사용자가 승인한 변경만 새 후보 실험 디렉터리에 적용하고, 원본 설정·코드·학습 결과·체크포인트는 수정하지 않는다. 후보 학습의 성공, 실패, 시간 초과 및 사용자 중단 상태를 감사 가능한 기록으로 남긴다.

## 실행 전제

- 변경 계획과 승인 기록이 모두 유효해야 한다.
- 승인 기록의 `plan_digest`가 현재 계획과 일치해야 한다.
- 한 개 이상의 변경이 승인되어야 한다.
- 변경 범주에 대응하는 원본 YAML 파일을 읽을 수 있어야 한다.
- 실제 학습은 사용자가 `--run-training`을 명시한 경우에만 시작한다.
- 가상환경을 활성화해 프로젝트와 동일한 Ultralytics 버전의 `yolo` 명령을 사용한다.

## 후보 디렉터리

```text
candidate-runs/execution-xxxxxxxxxxxx/
├── candidate/
│   ├── args.yaml
│   └── inference.yaml
├── audit/
│   ├── change-plan.json
│   ├── approval.json
│   └── execution.json
├── logs/
│   └── training.log
└── runs/
    └── train/
        └── weights/
            ├── best.pt
            └── last.pt
```

승인된 변경 범주에 필요한 후보 YAML만 생성한다. 이미 존재하는 후보 디렉터리는 덮어쓰지 않는다.

## 원본 보존과 복구

- 원본 YAML은 읽기 전용 입력으로 취급한다.
- 변경값은 새 `candidate/` 파일에만 기록한다.
- 학습 출력은 후보 디렉터리의 `runs/` 아래로 강제한다.
- 준비 도중 오류가 발생하면 새로 만들던 미완성 후보 디렉터리만 제거한다.
- 학습 실패나 중단 시 후보 디렉터리와 로그를 보존한다.
- 원본을 변경하지 않으므로 실패 시 운영 상태는 원본을 계속 사용하는 것으로 복구된다.

## 학습 상태

| 상태 | 의미 |
| --- | --- |
| `prepared` | 후보 설정과 감사 기록 생성 완료 |
| `running` | YOLO 학습 프로세스 실행 중 |
| `completed` | 종료 코드가 0이고 후보 체크포인트가 존재함 |
| `failed` | 프로세스 오류, 비정상 종료 또는 체크포인트 누락 |
| `timed_out` | 지정된 실행 제한 시간 초과 |
| `interrupted` | 사용자가 실행 중단 |

프로세스 종료 코드가 0이더라도 `best.pt` 또는 `last.pt`가 없으면 성공으로 처리하지 않는다.

## 명령 실행 안전성

- 셸 문자열을 실행하지 않고 고정된 인자 배열을 `subprocess.run`에 전달한다.
- 후보 설정, 출력 디렉터리와 run 이름을 명시적으로 지정한다.
- 시간 제한을 반드시 설정한다.
- 표준 출력과 오류를 `training.log` 하나에 기록한다.

## M5 완료 범위

- 승인된 항목만 후보 YAML에 반영
- 원본과 후보 파일 분리
- 계획·승인·실행 기록 연결
- 선택적 YOLO 재학습 실행
- 체크포인트 존재 확인
- 실패, 중단 및 시간 초과 상태 기록

후보 모델의 성능 평가와 원본 대비 비교는 M6에서 수행한다.
