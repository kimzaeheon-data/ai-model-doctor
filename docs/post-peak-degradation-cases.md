# 최적 epoch 이후 성능 하락 진단 테스트 사례 초안

## 목적

`post_peak_degradation` 규칙을 구현하기 전에 최고점 선택, 최고점 이후 학습 길이, 성능 하락 폭 및 경계값의 예상 판정을 합의한다.

이 규칙은 마지막 체크포인트의 성능이 학습 도중의 최고 성능보다 유의미하게 낮아졌는지 판단한다. 운영 모델로 `best.pt`를 사용해야 하는 이유와 early stopping 설정을 검토할 근거를 제공한다.

## 계산 방식 제안

### 사전 조건

- 최소 학습 기록: 10 epoch
- 비교 지표: validation `mAP50-95`
- 모든 epoch의 mAP50-95가 필요
- 하나라도 누락되면 `insufficient_data`

### 최고점 선택

```text
최고 mAP50-95 = 전체 기록의 최대 mAP50-95
최고점 위치 = 최고값이 여러 번이면 가장 최근 위치
최고점 이후 기록 수 = 전체 기록 수 - 최고점 위치 - 1
```

가장 최근 최고점을 사용하는 이유는 모델이 동일한 최고 성능을 다시 회복한 경우 오래된 최고점을 기준으로 불필요한 경고를 만들지 않기 위해서다.

CSV의 epoch 번호가 건너뛰거나 0·1 중 어느 값에서 시작하더라도 위치 계산에 영향을 주지 않도록 실제 기록 개수를 사용한다. 사용자 설명에는 원본 epoch 번호를 표시한다.

### 판정 기준

```text
필요한 최고점 이후 기록 수 = ceil(전체 기록 수 × 0.20)
성능 하락 폭 = 최고 mAP50-95 - 마지막 mAP50-95

최고점 이후 기록 수 >= 필요 기록 수
그리고
성능 하락 폭 >= 0.01
```

두 조건을 모두 만족할 때만 warning으로 판정한다.

---

## 사례 1. 학습 기록 부족

### 입력

```text
전체 기록: 8 epoch
```

### 예상 결과

```text
title: 최적 epoch 이후 성능 하락
status: insufficient_data
status_label: 판단 보류
severity: none
confidence: 1.0
```

### 사용자 설명

> 학습 기록이 8 epoch로 최소 기준인 10 epoch보다 짧아 최고점 이후 성능 변화를 판단할 수 없습니다.

---

## 사례 2. 마지막 epoch에서 최고 성능

### 입력

```text
mAP50-95: 0.30, 0.32, 0.35, 0.37, 0.39, 0.40, 0.42, 0.43, 0.44, 0.46
최고점: epoch 10, 0.46
마지막: epoch 10, 0.46
```

### 예상 결과

```text
status: pass
status_label: 이상 징후 없음
severity: none
confidence: 0.9
```

### 이유

최고 성능이 마지막 기록에 있어 최고점 이후 하락이 없다.

---

## 사례 3. 최고점이 일찍 나왔지만 유의미한 하락 없음

### 입력

```text
전체 기록: 10
최고점: epoch 6, 0.450
마지막: epoch 10, 0.444
최고점 이후 기록 수: 4
필요 기록 수: 2
하락 폭: 0.006
```

### 예상 결과

```text
status: pass
status_label: 이상 징후 없음
```

### 이유

최고점 이후 충분한 기록이 있지만 하락 폭이 0.01 기준보다 작다.

---

## 사례 4. 최고점 이후 성능 하락

### 입력

```text
전체 기록: 10
최고점: epoch 6, 0.450
마지막: epoch 10, 0.430
최고점 이후 기록 수: 4
필요 기록 수: 2
하락 폭: 0.020
```

### 예상 결과

```text
status: warning
status_label: 확인 필요
severity: medium
confidence: 0.9
```

### 사용자 설명

> 최고 mAP50-95는 epoch 6의 0.450이었으나 마지막 epoch에는 0.430으로 0.020 하락했습니다. `best.pt` 사용과 early stopping 설정을 확인해야 합니다.

### 원인 후보

- 최고 성능 이후 과도한 추가 학습
- 과적합 가능성
- 후반부 learning rate 또는 augmentation 영향
- Validation 지표의 진동

### 권장 확인

- 마지막 체크포인트 대신 `best.pt`를 평가에 사용하는지 확인
- 최고점 이후 validation loss 변화 확인
- patience 및 early stopping 설정 검토

---

## 사례 5. 정확히 경계값

### 입력

```text
전체 기록: 10
최고점 이후 기록 수: 2
필요 기록 수: 2
최고 mAP50-95: 0.450
마지막 mAP50-95: 0.440
하락 폭: 0.010
```

### 예상 결과

```text
status: warning
status_label: 확인 필요
severity: medium
```

### 이유

두 조건 모두 `이상`이므로 정확히 경계값을 만족하면 warning이다. 구현 시 부동소수점 오차를 고려한다.

---

## 사례 6. 최고점 직후라 관찰 기간 부족

### 입력

```text
전체 기록: 10
최고점: epoch 9, 0.450
마지막: epoch 10, 0.430
최고점 이후 기록 수: 1
필요 기록 수: 2
하락 폭: 0.020
```

### 예상 결과

```text
status: pass
status_label: 이상 징후 없음
```

### 이유

하락 폭은 크지만 최고점 이후 관찰 기록이 부족하다. 단 한 번의 지표 진동으로 경고하지 않는다.

---

## 사례 7. 동일한 최고점이 여러 번 등장

### 입력

```text
전체 기록: 10
mAP50-95 최고값 0.450이 epoch 4와 epoch 9에 등장
마지막 epoch 10: 0.430
```

### 예상 결과

```text
가장 최근 최고점: epoch 9
최고점 이후 기록 수: 1
status: pass
```

### 이유

Epoch 4를 선택하면 장기간 하락한 것처럼 보이지만 모델이 epoch 9에 최고 성능을 회복했다. 가장 최근 최고점을 사용해 오진을 줄인다.

---

## 사례 8. mAP50-95 누락

### 입력 예시

```text
전체 기록 중 한 epoch의 validation mAP50-95: null
```

### 예상 결과

```text
status: insufficient_data
status_label: 판단 보류
severity: none
confidence: 1.0
```

### 사용자 설명

> 일부 epoch의 mAP50-95가 누락되어 전체 최고점과 마지막 성능을 안정적으로 비교할 수 없습니다.

누락값을 0으로 대체하거나 해당 epoch를 임의로 제외하지 않는다.

---

## 사례 9. 원본 epoch 번호가 연속적이지 않음

### 입력 예시

```text
원본 epoch 번호: 1, 2, 3, 5, 6, 8, 9, 10, 12, 13
```

### 예상 처리

```text
전체 기록 수: 10
필요한 최고점 이후 기록 수: 2
```

원본 epoch 번호의 차이가 아니라 실제 제공된 기록 수로 관찰 기간을 계산한다. 단, 결과 설명에는 최고점과 마지막 기록의 원본 epoch 번호를 표시한다.

## `best_epoch` 필드와의 관계

Parser가 제공하는 `metrics.best_epoch`를 그대로 신뢰하지 않고 `metrics.epochs`의 mAP50-95에서 최고점을 다시 계산한다. 이렇게 하면 규칙이 사용한 수치와 근거를 직접 재현할 수 있다.

계산된 최고 epoch와 `metrics.best_epoch`가 다르면 첫 버전에서는 계산값을 사용한다. 불일치는 향후 Parser 경고 또는 입력 무결성 진단으로 분리한다.

## 중복 진단 처리

이 규칙은 학습 정체 및 과적합 의심과 동시에 warning일 수 있다. 규칙 엔진은 각각의 근거를 보존하고 챗봇이 관계를 설명한다.

> 최고 성능 이후 성능이 하락했으며, 같은 구간에서 validation loss도 증가해 과적합 가능성이 함께 관찰됩니다.

## 구현 전 승인할 기준

1. 전체 mAP50-95 기록에서 최고점을 다시 계산한다.
2. 동일한 최고점이 여러 번이면 가장 최근 위치를 사용한다.
3. 원본 epoch 번호가 아닌 실제 기록 수로 최고점 이후 기간을 계산한다.
4. 최고점 이후 기록이 전체의 20% 이상이고 하락 폭이 0.01 이상일 때만 warning이다.
5. 모든 epoch의 mAP50-95 중 하나라도 누락되면 판단을 보류한다.
6. 경계값을 정확히 만족하는 경우 warning에 포함한다.
7. 첫 버전의 warning 심각도는 `medium`으로 고정한다.
